## Milestone 1 — Baseline

**PASS** `backend/.venv/bin/python -m ruff format --check .` → `29 files left unchanged`
**PASS** `backend/.venv/bin/python -m ruff check .` → `All checks passed!`

Backend skeleton created:

- `backend/sentinel/common/` — config, SQLAlchemy models, DB session, security
  helpers, contracts, rate limiter, injectable clock
- `backend/sentinel/core/` — Core API (auth, workspaces, sources, monitoring, investigation)
- `backend/sentinel/ingest/` — Ingestion API (`POST /ingest/v1/events`)
- `backend/sentinel/detector/` — rule engine + worker
- `backend/alembic/` — migration owner (single `migrate` service owns the schema)

**PASS** `backend/.venv/bin/alembic upgrade head` → `Running upgrade  -> e00bbf48a74e, initial schema`
13 tables created: `alembic_version, alert_comments, alert_evidence, alert_history,
alerts, api_sources, detector_heartbeat, detector_jobs, memberships, security_events,
sessions, users, workspaces`.

**FAIL → FIXED** first autogenerated migration failed with
`relation "security_events_ingest_seq_seq" does not exist`.
Root cause: the `ingest_seq` column used a hand-written `nextval(...)` server default
without creating the sequence. Fix: switched to `sqlalchemy.schema.Identity(always=False)`
and regenerated the migration. Rerun outcome: `alembic upgrade head` succeeded.

## Milestone 2 — Functional vertical slice

**PASS** `pytest ../tests/test_core_api.py` → 18 passed
Registration, login, logout, session revocation, CSRF rejection, workspace CRUD,
member management, source creation/rotation/revocation, dashboard aggregation and
alert listing are implemented and covered.

**PASS** `pytest ../tests/test_ingest_api.py` → 12 passed
Valid event → 202; identical retry → 200; same event id with different content → 409;
invalid payloads → 422; revoked key → 401; event and detector job created together.

**FAIL → FIXED** `source_ip="not-an-ip"` reached PostgreSQL and raised
`InvalidTextRepresentation ... type inet`.
Root cause: the contract only constrained the length of the IP string. Fix: the
contract now uses `pydantic.IPvAnyAddress`. Rerun outcome: the invalid payload is
rejected with 422 before it reaches the database.

**FAIL → FIXED** an identical retry returned `202` instead of `200`.
Root cause: the route always returned the 202 response model. Fix: the duplicate
branch now returns an explicit `Response` with status 200 and the `duplicate` body.

## Milestone 3 — Detection

**PASS** `pytest ../tests/test_rules.py` → 16 passed
Threshold−1, exact threshold, window boundary (start excluded / end included),
source separation, IP separation and stable ordering by ingestion sequence.

**FAIL → FIXED** events from another source/IP were counted toward the threshold.
Root cause: `select_window_events` filtered only by the time window. Fix: the
selection now requires a matching `source_id` and `source_ip`.

**FAIL → FIXED** `alerts.source_ip = '203.0.113.10'` raised
`operator does not exist: inet = character varying`.
Root cause: the `INET` column was compared with a plain string parameter.
Fix: added `inet_equals()` in `sentinel/common/models.py`, which casts the literal
to `INET`; used in the detector and in the event filter.

**FAIL → FIXED** the frontend-facing traffic chart returned no buckets for a
workspace without sources.
Root cause: `_traffic_buckets` returned an empty list when there were no sources.
Fix: the buckets are now always zero-filled over the requested range.

**PASS** `pytest ../tests/test_detector.py` → 10 passed
Alert creation on a crossing, evidence links, job completion, idempotent reruns,
suppression inside the window, a fresh crossing after suppression, per-IP counting
and the retry path with a sanitized failure message.

**FAIL → FIXED** `GET /api/workspaces/{id}/members` returned 400.
Root cause: the workspace dependency only read the `X-Workspace-Id` header, but the
route already carries the id in the path. Fix: the dependency prefers the path
parameter and falls back to the header.

**FAIL → FIXED** `POST /api/auth/logout` returned an empty 200 instead of 204.
Fix: the response status is set explicitly to 204.

**PASS** `pytest ../tests/` → **56 passed**
